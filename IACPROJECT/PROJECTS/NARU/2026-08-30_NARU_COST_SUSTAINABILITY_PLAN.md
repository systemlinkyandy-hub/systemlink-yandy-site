# NARU Cost Sustainability Plan

- Project: TikTok AI Liver / NARU
- Date: 2026-08-30 JST
- Coordinator: アーク
- Status: ADOPT FOR RESTART

## 1. 目的

ナルを「起動しただけで従量課金が走るPoC」から「運用可能なAIライバー」へ移行する。
旧実装の完成度を維持しつつ、OpenAI系LLM・ElevenLabs TTS等の従量課金を発話ごとに無制御で発生させない。

## 2. 最優先原則

1. SAFE BOOT
   - 起動直後は無発話待機。
   - AUTOは明示操作でのみ開始。
   - 起動時に外部APIを自動呼出ししない。

2. COST GATE
   - 発話前に「この応答で外部課金を使う必要があるか」を判定する。
   - 無視／定型／ローカル処理で足りる入力を外部LLM/TTSへ送らない。

3. SHORT RESPONSE FIRST
   - ライブ通常応答は短文を既定にする。
   - 長文はDISCUSSION等、明示モードだけで許可する。

4. TIERED RESPONSE
   - Tier 0: 無応答／表示のみ
   - Tier 1: 定型応答・キャッシュ済み音声
   - Tier 2: 軽量LLM + 低コスト音声
   - Tier 3: 高品質LLM + ElevenLabs
   通常コメントを常にTier 3へ送らない。

5. CACHE
   - 挨拶、ありがとう、初見対応、定番リアクション等は音声キャッシュを再利用する。
   - 同一テキストを都度TTS生成しない。

6. BUDGET LIMIT
   - セッション上限、日次上限、警告閾値を設定可能にする。
   - 上限到達時は自動で外部課金を止め、ローカル／定型モードへ降格する。

## 3. 実装優先順位

### P0
- デフォルトAUTO禁止
- 外部API呼出しON/OFFスイッチ
- 1発話ごとの文字数上限
- セッション発話回数上限
- TTSキャッシュ

### P1
- 外部LLM/TTS利用ログ
- 推定コストログ（モデル・文字数・回数単位）
- comment / LLM / TTS / playback の非同期化
- 重複コメント抑制

### P2
- ローカルTTS候補の差し替え可能化
- 軽量／高品質モデルのルーティング
- ギフト・重要コメントのみ高品質応答へ昇格

## 4. 旧ナルで残すもの

- アバター描画
- 瞬き
- 音声連動口パク
- AUTO / CHAT / DISCUSSION の考え方
- OBS連携
- 発音辞書
- 字幕／コメント表示

これらは再利用資産であり、コスト問題を理由に捨てない。

## 5. 完了条件

最低限、以下を満たすこと。

- 起動後30分放置しても外部API課金が0
- CHATで1コメント処理しても次コメント受信が止まらない
- 定型コメントは外部LLM/TTSを使わず応答可能
- 高品質応答が必要な場合だけ外部APIを使う
- セッション上限到達時に自動停止またはローカル降格
- 1セッションあたりの外部API利用回数・文字数を確認できる

## 6. 役割

- 佐藤: 実装
- 黒瀬: 独立レビュー。コスト漏れ、無限ループ、silent fallback、課金暴走を重点確認
- スネーク: 現行OpenAI/ElevenLabs/TikTok側の利用条件・制約確認
- 田中: 収益化ラインと運用原価の比較整理
- アーク: Router、状態・ACK・重複・未処理管理

## 7. Owner burden rule

ケイへコード探索、料金調査、比較表作成、AI間転記、レビュー回収を戻さない。
