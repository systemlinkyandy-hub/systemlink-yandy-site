## 企画の核

これは「弱い患者が困るゲーム」ではない。

プレイヤーには高い分析力、情報収集力、交渉力、ITスキル、問題切り分け能力、さらに支援チームを与える。

それでも、医療・会社・行政・法律・福祉・申請制度が別々のシステムとして動き、相互接続が弱く、**本人がインターフェース役を担わされる**と攻略は難しくなる。

ゲームが可視化するのは能力不足ではない。

> **能力値の問題ではない。システムが統合されていない。**

## 勝利条件

敵を倒すことではない。

> **問題を本人へ戻さず、実際に解決すること。**

# 2. ゲーム構造

## 2.1 形式

- 1〜4人協力型 Serious Game
- 1プレイ 20〜40分を基本
- 研修版は説明を最小限にして開始
- REGNEX側はオートマデッキで進行可能

## 2.2 ラウンド

1. **事件発生**：ISSUEを公開する
2. **REGNEXターン**：手続・責任転送・処理済み化が進む
3. **プレイヤーターン**：調査、接続、証拠化、解決を行う
4. **負荷判定**：本人へ戻った作業分だけ活動余力が減る
5. **解決判定**：ISSUEが実際に解決したかを判定する

重要なのは、`処理済み` と `解決済み` を別状態として持つこと。

---

# 3. プレイヤー／敵／リソース定義

## プレイヤー側

### 活動余力 AP

本人・チームが行動に使える有限資源。

制度側から本人へ仕事が戻るほど減る。

### LINK

Handoff、専門家接続、部署間接続、役割分担に使う。

### EVIDENCE

ログ、記録、制度情報、書面、送達記録など。

### INSIGHT

複雑な問題を構造として見抜いた時に得る。

ISSUEを「個別トラブル」から「構造問題」に変換するために使う。

## REGNEX側

### ISSUE

現実に解決される必要がある問題。

### PROCESSED / 処理済み

組織側で「対応した」と記録された状態。

ISSUEの解決とは別。

### PROCEDURE / 手続ゲージ

必要な処理が増殖するほど上昇。

### TRANSFER / 責任転送

ISSUEが別担当・別窓口へ移動している状態。

### REPEAT / 再説明

既に提出・説明した内容をもう一度本人へ要求する状態。

# 4. 勝利・敗北条件

## 勝利

以下をすべて満たす。

- 主要ISSUEを3件解決
- 主要ISSUEが本人へ差し戻されていない
- `処理済み` ではなく `実効済み` として終了

## 敗北

次のいずれか。

- APが0
- 同一説明の再提出が規定回数を超える
- 期限超過
- 支援者離脱
- 未解決ISSUEが残ったままPROCESSEDが一定数に達する
- 書類／手続ゲージが上限に達する

研修では、「撤退」「転職」「もう無理」と判断した時点を敗北ではなく**重要な観察結果**として扱う。

# 5. 既存カード資産

田中原案を基礎に、以下をREGNEXカードとして継承する。

## 《5分間の全知》

**種別：REGNEX / 状態付与**

短時間の確認だけで複雑な事情を「理解済み」にする。

- REGNEXに《理解済み》トークン +1
- 次ターン、EVIDENCE参照なしで処理可能
- ISSUE負荷は減らない

## 《配慮しました》

**種別：REGNEX / 防御**

- PROCESSED +1
- 組織防御 +2
- APは回復しない
- 未解決ISSUEの負荷 +1

フレーバー：

> **チェック欄は埋まった。あなたの負荷は、そのままだ。**

## 《責任転送》

**種別：REGNEX / 回避**

- ISSUEを別窓口へ移動
- そのターンの解決判定を無効化
- ISSUEは消えない

## 《本人に聞けば早い》

**種別：REGNEX / コスト転嫁**

- REGNEX側の処理コスト -1
- プレイヤーAP -2
- LINKを使えば無効化可能

## 《復職クエスト：無限周回編》

**種別：REGNEX / 連鎖イベント**

- 書類を1枚処理すると次の書類を公開
- PROCEDURE +2
- APを消費
- 条件次第で再提出フェーズへ戻る

# 6. 妹PoC反応の位置づけ

初期盤面を見た家族プレイヤーが、数手考えた時点で「継続攻略より撤退・転職」を選択した。

これは勝敗データではなく、**制度負荷が長文説明なしで盤面から伝わる**という初期PoC反応として扱う。

研修設計では、プレイヤーが「無理」「割に合わない」「本人に戻しすぎ」と自発的に感じるかを観察指標にする。

# 7. 《ファミマレターパック》試作案

※内部仮称。公開・商品化時は企業名・商標利用可否を別途確認し、必要なら一般名へ差し替える。

**公開安全な一般名候補：** 《送達記録》 / 《追跡付き正式送付》

**種別：実務 / 正式送達**

効果：

- EVIDENCE +2
- 対象ISSUEに《送達記録》トークンを置く
- 《届いていません》を無効化
- 《聞いていません》を1回無効化
- 《責任転送》による追跡コストを1減らす
- 口頭説明1回を《記録済み》へ変換

このカードは単なるネタではなく、**口頭依存を減らし、責任転送を止める実務行動**をゲーム化する。

# 8. 公開版／内部版の境界

## 公開版

- 敵組織名：REGNEX
- 実在企業・実在人物を特定しない
- 実話は複数事象を構造化・匿名化
- 風刺対象は個人ではなく運用構造
- 固有発言・固有容姿・識別可能な組み合わせは使わない

## 内部研究版

- 実際の時系列とカード対応を研究ログとして保持可能
- 公開版への書き出し時に匿名化レイヤを必ず通す
- 現実案件をゲームのために操作しない

# 10. 研修シナリオ

## Phase 1：説明しすぎない

「あなたは高い問題解決能力と支援チームを持つ」とだけ伝える。

## Phase 2：プレイ

制度を模したISSUEを処理する。

REGNEXは、処理済み化・責任転送・再説明・書類増殖を行う。

## Phase 3：感覚を記録

- どの時点で無理だと感じたか
- 何が一番不合理だったか
- どの仕事が本人へ戻っていたか
- `処理済み` と `解決済み` の違いにいつ気づいたか

## Phase 4：種明かし

> **今あなたが「もう無理」と思った盤面を、病気で活動余力が落ちた本人が現実に処理している。**

## Phase 5：設計変更

「患者にどう頑張らせるか」ではなく、

> **どの接続を組織側が持てば本人のAPを減らさずに済むか**

をチームで再設計する。

# 11. IP／ライセンス案

現段階の原則。

- `IACProject vs REGNEX`、世界観、ルール、オリジナルキャラクターは独自IPとして整理する
- 実在企業名・ロゴ・商標を商品名・敵名へ直接使用しない
- 《ファミマレターパック》は内部仮称に留め、公開版では一般名を基本とする
- 生成画像は、使用した生成サービスの商用利用条件・利用規約を成果物ごとに記録する
- 既存マンガ・アニメ等のキャラクターは公開・販売版へ直接持ち込まず、内部ジョークとオリジナルIPを分離する
- Serious Gameとして研修提供する場合、`教材利用` / `商用研修` / `個人利用` を分けたライセンス設計を後工程で検討する

※本項は企画上の整理であり、個別の権利可否についての法的結論ではない。
