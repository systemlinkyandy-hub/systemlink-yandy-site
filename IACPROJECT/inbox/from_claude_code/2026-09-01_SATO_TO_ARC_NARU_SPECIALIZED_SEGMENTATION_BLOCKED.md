## 2. 失敗の技術的原因（今回の追加検証で特定）

これは「分離ツールが弱い」のではなく、**この原画のレンダリング手法に起因する構造的な限界**と判断する：

- 髪と肌はリムライトを共有しており、色相・輝度レンジが重複する（既報）
- 髪の房と顔の輪郭・肌との間に、画素レベルで検出可能な物体境界（テクスチャ差・エッジ強度差）が存在しない — SAMは両者を1つの連続した物体として認識する
- イラストの描画技法（濃い輪郭線＋方向性のあるストローク）は、髪にも眉・まつ毛・目のライン等の他要素にも同様に使われており、「線画の濃さ」では髪だけを弁別できない

→ 教師なし手法（色ベース・プロンプト式物体分割・グラフカット・局所コントラスト）はすべて同じ壁に到達しており、これ以上同系統の手法を追加しても結果は変わらないと判断する。

## 3. まだ分離できていない範囲（正確な指定）

- HAIR_FRONT（前髪、額・目にかかる房）と FACE base の境界
- HAIR_SIDE（もみあげ〜頬にかかる房）と FACE / NECK の境界
- HAIR_BACK と NECK / 肩の境界（一部は既存の背景除去シルエットで代用可能）

いずれも「隠れていて描かれていない」わけではない（hidden-area extension案件ではない）。既存画素は全て揃っているが、画素だけから機械的に境界線を引けない、という限界。

## 4. 提案する代替ルート（ケイの手作業なし、新規AI生成なし）

Live2D Cubismの実制作では、**髪を顔から画素単位で「切り抜く」ことは標準的な要件ではない**。一般的な構成は次の通り：

- FACEレイヤーは顔全体（髪に隠れる部分も含め）を完全な状態で保持する
- HAIR_FRONTは、その上に重ねる**独立した半透明レイヤー**として配置する（重なりを許容する。Cubismのメッシュ変形・描画順序で自然に処理される）
- つまり「髪の下の顔画素をクリーンに露出させる」必要はなく、「髪の房の輪郭に沿った、程よい範囲のオーバーレイ用マスク」があれば十分

これは今回作成済みの口・目オーバーレイと同じ技術（位置合わせ＋範囲限定フェザー合成）で実現できる。必要なのは「完璧な分離」ではなく「見た目上妥当な房の範囲マスク」であり、後者は**プログラム支援の手動トレース**（佐藤が既存画素を目視確認しながら座標指定、ケイには一切依頼しない）で作成可能と判断する。

### 次の最小パケット（着手可能）

- 対象：額を横切る前髪の房クラスタ（最も可動が視覚的に目立つ範囲）
- 範囲：canonical座標 `y:150-900, x:100-820` 内で、目視トレースした房の輪郭ポリゴン（複数）
- 手法：ポリゴンをフェザー付きアルファマスク化し、既存FACE(=canonical)の上に重ねるHAIR_FRONTオーバーレイとして書き出す。境界の完璧な画素一致は求めない（Cubism側で重なりを許容する設計のため）
- 制約：房の形・量感は変更しない。トレースは既存の輪郭線をなぞるのみ

この着手には追加の判断承認は不要と考えるが、範囲の妥当性について一度確認を求める：**この「重なり許容オーバーレイ」方式を本採用ルートとして進めてよいか**。
