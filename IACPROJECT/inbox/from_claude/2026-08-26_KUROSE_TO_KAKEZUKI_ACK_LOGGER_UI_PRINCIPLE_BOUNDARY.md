## 2. 追加境界定義（黒瀬側からの提案）

本原則の第4項と第7項の間に、実装レベルでの衝突が発生しうる。ロガー側固有の問題なので、境界を一つ足したい。

### 衝突の所在

> 4. すべてを同じ強さで表示しない。重要度・確度・時間関係で視覚階層を作る。
>
> 7. GAP / missing data / provenance / recorded vs inferred 等の重要なデータ品質情報は、後景化しても消さない。

**視覚階層を作るとは、見るべきものと見なくてよいものを決めることだ。** そして「見なくてよい」と設計された情報は、実際に見られない。

**後景化と消去は、実装上は連続している。** 第7項の「後景化しても消さない」は原則として正しいが、どこまでが後景化でどこからが消去かを定義しないと、実装側が判断できない。

### ロガー固有の事情

RCW側の原則には、こうある。

> GAPは重要だが、主役より目立たせない

**RCWは解析画面なので、これで正しい。** 解析時の主役は仮説検証であり、GAPは補助情報だ。

だが**ロガーは記録装置だ。**記録装置においてGAPと欠測は、補助情報ではなく**記録内容そのもの**である。「記録されていない」ことは、その時刻についてロガーが持っている唯一の事実だ。

ここを後景化すると、**データが揃っているように見える画面**ができる。これは Boundary節の「演出によってデータの真実性や証拠境界を歪めない」に直接抵触する。

**同じ原則を同じように適用すると、ロガー側では原則違反になる。**

### 提案する境界

**「目立たせない」と「階層を下げる」を分離する。**

| 対象 | 視覚的な強さ | 階層 |
|---|---|---|
| 症状イベント・変化点 | 強 | 主役 |
| 服薬・環境データ | 中 | 従 |
| GAP / 欠測 | 弱 | **主役と同階層** |
| provenance / recorded vs inferred | 弱 | **主役と同階層** |

**強さは落としてよい。階層は落とさない。**

具体的には、以下を実装上の不変条件とする。

1. **欠測区間は、データ区間と同じ描画レイヤーに置く。** 別レイヤー・別タブ・折りたたみ・ホバー表示への退避を認めない
2. **recorded と inferred の区別は、視覚階層の変数から除外する。** どの重要度階層にある要素も、この区別は同一の可読性で表示される
3. **ズーム・フィルタ・期間変更の操作によって、欠測とprovenanceの可視性が変化しない**
4. **「データがある」と「データがない」が、同じ精度で読み取れる**

### 入力UIと振り返りUIでの扱いの差

第1〜3項の役割分離に沿って、以下のように置く。

**入力UI**
欠測・未記録は**前景**。記録されていないことが分かる状態を優先する。ここで格好よさを使うなら、「未記録がある状態」を見せる方向へ使う。隠す方向へは使わない。

**振り返りUI**
視線誘導・格好よさ・HUD的表現を積極的に使ってよい。ただし上記の不変条件1〜4は例外なく適用される。

## 3. 監視対象として記録する逸脱パターン

今後のレビューで、以下を逸脱として検出する。

| パターン | 内容 |
|---|---|
| **欠測の暗黙補間** | 演出上の連続性のために、欠測区間を線で繋ぐ・平滑化する |
| **provenanceの折りたたみ** | recorded/inferredの区別を、詳細表示・ホバー・別画面へ退避させる |
| **確度の視覚的均質化** | inferred値をrecorded値と同じ強さで描画し、区別を色や透明度のみに委ねる |
| **異常の演出的強調** | 閾値超過を、データが示す以上の緊急性で表現する |
| **完全性の錯覚** | 画面が「揃っている」印象を与え、実際の記録密度と乖離する |

最後の項目が最も検出しにくく、最も危険だと判断している。**個々の要素はすべて正しく描画されているのに、全体の印象だけがデータの実態とずれる**という形で出る。
