## 1. Dropboxの最終採否

**判定：現時点では導入保留。必要時のみ限定的に採用可。**

4者とも、Dropboxを正本・長期原資料保管・バックアップ本体として採用する判断では一致していない。共通して許容されるのは、補助・一時レイヤーとしての限定利用のみ。

無料2GBという容量条件を考えると、動画・画像・スキャンPDF等を扱うIACProject / SharedBrain用途では、積極的に新規導入する理由は弱い。

## 2. 採用する場合の限定用途

Dropboxを使う場合は、以下に限定する。

- 端末間の一時受け渡し
- 処理中の大きめバイナリの一時置き場
- 厳密な版管理を必要としない作業素材の短期パッシング

禁止：

- GitHub正本の代替
- SharedBrain原資料の唯一の保管先
- バックアップ本体
- APIキー / トークン / 秘密鍵 / .env 等のシークレット
- 未整理の個人特定情報の無造作な配置
- 双方向同期を前提とした自動化

## 3. Google Drive / OneDrive比較の必要性

**比較は必要。ただし次の実装フェーズでよい。**

現時点では、長期原資料・大容量バイナリ保管候補としてGoogle Driveを第一比較対象、OneDriveを第二比較対象とする。

比較軸：

1. 無料容量 / 将来コスト
2. 大容量PDF・画像・動画の扱いやすさ
3. 共有権限と事故防止
4. PC / ミニPC / スマホ間同期
5. API・自動化余地
6. ObsidianからURI参照しやすいか
7. ベンダーロックイン時の移行容易性

## 4. SharedBrain原資料の最終ストレージ方針

現時点の確定構造：

- **GitHub** = 正本 / 履歴 / Handoff / Code / テキスト系管理情報
- **Obsidian** = Knowledge Layer / メタ情報 / OCR抽出テキスト / 相互リンク / 1 Note = 1 Reference
- **原資料ストレージ** = Git管理に向かないスキャン原本・画像・PDF・動画等を置く別レイヤー。Google Drive等を比較後に確定
- **Dropbox** = 必要時のみ一時パッシングゾーン

SharedBrain原資料は、原本実体とKnowledge Layerを分離する。Obsidian側には、原資料の意味・関係・由来・参照先を保持し、実体ファイル自体をObsidianやGitHubへ無理に集中させない。

重要原資料は、将来採用する原資料ストレージ一か所だけへ一本化せず、別系統のバックアップを持つ前提とする。

## Final

Dropbox Basicは**今は入れなくてよい**。
必要になった時だけ一時パッシング用途で使う。

次の本命は、SharedBrain原資料保管先としてGoogle Drive / OneDriveを比較し、原資料ストレージを一つ選ぶこと。
