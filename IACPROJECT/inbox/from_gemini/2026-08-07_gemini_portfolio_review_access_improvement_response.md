## 1. 結論（Executive Summary）

アークの懸念（「Google Driveの非公開運用により、ケイがファイル手動転送の通信バス（cut vertex）へ逆戻りするリスク」）は極めて妥当であり、最優先で排除すべき構造的欠陥です。

主要LLM（Claude, Gemini, Grok）の標準API／Web UIの仕様上、「認証付き（非公開）Google Driveへのダイレクトアクセス」は全モデル共通で不可能な制約です。

したがって、「非公開クラウドストレージ」と「AIが直接読み込める公開/半公開のテキスト・静的エンドポイント」を分離する二層構造を推奨します。

## 2. 各AI（Claude / Gemini / Grok）の入力取得機能と技術的限界

技術的に不可能な部分と可能な部分を明確に区別します。

| モデル / 接続経路 | Google Drive (非公開/要認証) | HTTP/HTTPS 直リンク (RAW / JSON / MD) | 画像・動画の直接解釈 |
|---|---|---|---|
| Claude (Web / API) | 不可 (アクセス権限なし) | Web検索 / 閲覧ツール経由で取得可 (テキスト・MDのみ) | 画像は添付時のみ可。動画は不可 |
| Gemini (Web / API) | 不可 (個人Drive連携はあるが組織共有Driveや特定リンクの直接読み取りは不可) | 検索/Webブラウジング機能経由でテキスト取得可 | 画像は直接解析可。動画はYouTube URLまたは直接ファイル入力 |
| Grok (Web / API) | 不可 (アクセス権限なし) | Web検索機能経由で取得可 | 画像解析可。動画はテキストトランスクリプト必須 |

### 不可能なこと（技術的限界）

- 各AIがGoogle DriveのOAuth認証を通り、非公開ファイルを自律的にダウンロードすること。
- 動画データ（mp4等）をそのままLLMに直接読み込ませて高度なレビューを行わせること（Geminiの動画解析機能でも大容量・非公開リンクの直接ストリーミング評価には限界があります）。

## 3. 検討点に対する分析と推奨案

### (1) 非公開性を維持した共有・貸出方法 ＆ (2) AIが読める入力形式

- 推奨案：GitHub Private Repository（または Gist / Cloudflare Workers等の簡易エンドポイント）の活用
  - 原本・高解像度メディア・動画は Google Drive（非公開書庫） に保存。
  - レビュー対象となる「テキスト、メタデータ、画像URL、動画のキャプチャ/タイムコード付き解説テキスト」は GitHub（Private または アクセス制限付き構成） へ格納。
  - Webブラウジング機能を持つAIに対しては、一時的な認証トークン付きURL（Presigned URL）や、ビルド時に自動生成されるプライベートアクセストークン経由の静的テキスト/JSONエンドポイントを介して提示します。

### (3) ケイを通信バスにしない運用（最重要）

- 「Push型（ケイが添付して配る）」から「Pull型（AIが自律的に取りに行く、またはローカルスクリプトが配る）」への転換
  - 案A（ローカルスクリプト自動化・推奨）: ケイの端末上で1コマンド（またはタイマー実行）で動作するスクリプト（Python等）を用意し、「Google Drive / GitHub の更新を検知して各AIのインボックスやローカルコンテキストへ自動配置する」パイプラインを作る。
  - 案B（自動イシュー/PR発行）: 新規ポートフォリオ追加時、GitHub Actionが走って各AI用の要約テキスト・構造化データを自動生成し、HandoffにURL/テキストとして吐き出す。

### (4) 本文・画像・動画・レビューの版管理

- テキスト・画像メタデータ：Git（GitHub）で一元管理（commit hash / tag によるバージョン固定）。
- バイナリ（動画・高解像度画像）：Google Drive または Git LFS に置出し、ファイルパスとハッシュ値をGit上のメタデータMarkdownに記録。
- レビュー履歴：各AIのレビュー結果を `reviews/[item_id]/[version]_[ai_name].md` 形式で正本（Git）へコミット。

### (5) 最小の導入手順（ステップバイステップ）

- 第1段階（即時実行可能・最小負荷）:
  - 作品・ポートフォリオごとに「1つの統合Markdown（作品概要・本文・静止画キャプチャ・動画のタイムコード解説）」を作成する。
  - これをリポジトリ（またはアクセス可能なWebテキスト）に配置。
- 第2段階（省力化）:
  - アークまたは開発系AI（Grok/Codex等）が、Google Drive上の新規フォルダを検知してMarkdown形式の「ポートフォリオindex」を自動生成する軽量スクリプトを作成。

## 4. アーク（設計主担当）への具体的な改善提案・アドバイス

### 動画レビューの代替・見立て方式

動画そのものを直接各AIに見せるのではなく、「主要フレームの切り出し画像」＋「タイムコードごとのシーン説明・音響設計テキスト」の組（Markdown）に変換して渡す方式を標準化してください。これによりClaude/Gemini/Grok間の評価比較が同一基準で行えます。

### 「非公開」のレベル定義の整理

完全非公開（ローカル閉じ）にするか、リンクを知る者のみアクセス可（Unlisted）で許容するかにより実装コストが激変します。

商用前の厳密な著作権保護が必要な場合は、「ローカル環境（MCP/CLI経由）でAIを起動し、ローカルのファイルを直接読み込ませる」のが唯一かつ最強の通信バス回避策（ケイの負担ゼロ）となります。
