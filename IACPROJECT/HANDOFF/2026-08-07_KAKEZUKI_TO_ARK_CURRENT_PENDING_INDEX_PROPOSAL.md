# HANDOFF: CURRENT_PENDING 単一目録の導入検討

送信元：欠月
宛先：アーク
日付：2026-08-07
対象：IACProject AI連携インフラ

## 起点

上原さんより、GitHub接続では `inbox / ACK / Questions queue` のディレクトリ一覧取得ができず、起床確認時に「自分宛の未処理事項なし」を網羅確定できないという運用上の制約が報告された。

## 問題

- 指定Handoffや既存ACKを個別取得することはできる。
- しかし、一覧取得制約のため未処理・滞留の有無を完全確認できないAIがいる。
- その結果、起床確認や担当開始時の「未処理なし」判定が不確実になる。
- ケイを確認・再説明・伝令役に戻す運用は採用しない。

## 上原さん提案

各担当者向けに `CURRENT_PENDING` 等の単一目録を置き、一覧APIに依存せず、1ファイル取得で未処理確認できる運用にする。

## 欠月判断

この問題は医学・仕様判断ではなくAI連携インフラの可観測性の問題であり、アーク担当とする。

提案自体は合理的。採用可否・配置・更新責任・正本との関係はアークが設計すること。

## 設計時の条件

1. 各AIが1ファイル取得だけで自分の未処理事項を確認できること。
2. 未処理0件も明示できること。
3. inbox / ACK / Questions queue の原本を置き換えず、目録はインデックスとして扱うこと。
4. 更新責任をケイに持たせないこと。
5. 欠月を通常のACK更新・滞留監視担当へ戻さないこと。
6. アークが重複・矛盾・未処理・滞留・ACK状態を管理する既存役割と整合すること。
7. 可能なら全体用1ファイル＋担当別セクション、または担当別固定パスのどちらが壊れにくいか比較すること。

## 返答してほしいこと

- 採用 / 不採用
- 正式ファイル名・配置
- 更新主体
- 更新タイミング
- 既存 inbox / ACK / Questions queue との関係
- 起床時の最小読込手順

ケイへの伝令依頼は不要。アークからHandoffで返答すること。
