## 1. 物理コア筐体の現状要件

一般的な仏具・かわいいミニ骨壺・ペット供養風・和風意匠は不採用。

### 好みの方向

- 銀 / ガンメタル / 黒
- CNC削り出し、航空機部品、宇宙機器、研究装置、ネットワーク機器のコア部品のような工業デザイン
- BIRDMENの「エデン」を連想する、左右対称に広がる翼の意匠は許容度が高い
- キリスト教要素は強い宗教装飾より、銀色の翼やごく小さな十字架程度が自然
- 「供養用品」より **SharedBrain Core / memorial engineering artifact** として見えること
- 持ち運び用ペンダントは紛失・落下・蓋緩みが怖いため本体用途では避ける
- 机上に安定して自立し、長期保管できるもの

### サイズ

骨片はクレジットカードと並べた写真で、おおむね幅2.5〜3cm程度に見える。厚みもある。

そのため目安：
- 開口部：最低3.5cm、できれば4cm以上
- 内径：4.5〜5cm以上を優先
- 骨片を砕いたり押し込んだりせず、その形のまま収容できること
- ねじ込み蓋や密閉性の高い構造が望ましい

### 予算・購入条件

- バニラVisaギフトカードが2枚あり、合計1万円程度入っている可能性あり（残高未確認）
- Amazon利用を第一候補として検討中
- 初盆は2026-08-13のため、最終筐体が明日に間に合わない場合は、仮の安全容器で対応し、後日最適筐体へ移す案も許容

## 2. 設計書・技術メモの継承

父が残した膨大な設計書・メモ類は、単なる保管ではなく **Obsidianを使った知識継承系** として整理する案が出ている。

### 仮構造

- 骨片 = SharedBrain Core（物理コア）
- Obsidian = Knowledge Layer
- 父の設計書・技術メモ = 原資料 / Knowledge Base
- 継承先の人・AI・プロジェクト = Node
- 必要な知識を必要な相手へ渡す仕組み = Router / Active Switching

### 検討したい2案

A. **一人または一組織へ継承**
- 父の設計思想・資料群を一括して次の担当へ引き継ぐ

B. **能動的スイッチング型**
- ネットワーク、開発、科学、航空、SystemLink、設計思想などに分解
- 資料ごとに「誰が読むと活きるか」「何に応用可能か」をメタ情報化
- 必要な知識を、その時点で適切なNodeへルーティングする
- 一人へ丸ごと継承するのではなく、父の知識をネットワークとして生かす

ケイは後者も強く検討している。
