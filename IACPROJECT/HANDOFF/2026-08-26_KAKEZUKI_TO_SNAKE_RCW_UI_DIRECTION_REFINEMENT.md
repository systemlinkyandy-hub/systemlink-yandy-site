## 背景

Clinic 7-Day View の実機確認で、画面としては正しく動作している一方、ケイ本人から「どう見ればいいか分からない」「見栄えはいいが、この図で何を言いたいのか分からない」「混乱するしテンションが下がる」という明確なUIフィードバックが出た。

ここから、RCWのUI原則を次の方向で固定して煮詰める。

## 共通原則

### 1. 可読性
可読性は単なる文字サイズや情報量の少なさではない。

**注意を引く → 視線を誘導する → 何と何を比較するか示す → 重要度を視覚階層で伝える**

ことを指す。

### 2. 格好よさ
格好よさは装飾ではない。

ケイ本人の長年の観察として、Iron Man的HUD、ゲームUI、短い英語ラベル、Metal Gear Solidのような「見たい・触りたい・集中したい」と思わせるUIは、解析に向かうためのテンション・モチベーション・注意資源を引き上げる。

したがって、

**Coolness / immersion / engagement は、人間側の解析リソースを起動する設計要因**

として扱う。

ただしこれは医学的に確立した因果ではなく、まずは本人観察およびHuman Factors上の設計仮説として扱う。

## 画面役割の分離

RCWでは今後、画面の役割を混ぜない。

### Analysis UI
目的：判断・比較・仮説検証

要件：
- 何を判断する画面か一文で言える
- 最初に見る点が分かる
- 次に見る点が分かる
- 比較単位が明確
- 症状／服薬／環境／活動の関係を追いやすい
- GAP・provenance・recorded/inferredを隠さない

### Cockpit / Workbench UI
目的：研究状態の俯瞰、没入、やる気の起動

要件：
- 格好いい
- 高密度でよい
- 研究している感覚を強く持てる
- 状態を眺めたくなる
- 分析UIほど即時可読性を要求しない

## Clinic 7-Day View の現在判定

機能としては実装済みだが、情報設計は未完。

現在の問題：
- 7日横並びの意味が弱い
- GAPが主役化している
- 症状／服薬が視線の起点になっていない
- 「この7日で何を見るのか」がUIから立ち上がらない
- 見栄えはよいが、比較判断へ誘導しない

## 欠月の暫定方針

Clinic 7-Day View は、

> 症状が出た日と出なかった日で、服薬・活動・環境条件に何が違ったかを見る

という目的へ絞る。

候補構造：
- 1日 = 1列、7日を横比較
- 症状日を視線起点として強調
- 同日の服薬を次に見る
- その前後の環境変化を次に見る
- 他日との差分へ視線を送る
- GAPや補助情報は後景化

ただし、この具体構造はまだ最終採用ではない。

## スネークへの相談事項

外部視点／UI監査として、次を返してほしい。

1. 上記の「Attention × Motivation × Readability」原則に矛盾や抜けがないか
2. Clinic 7-Day Viewを「何を判断する画面か一文で説明できる」状態へ持っていく最小構造案
3. Iron Man / tactical HUD / game UI 的な没入感を、分析誤誘導なしに取り込むための具体ルール
4. 日本語UIに短い英語ラベルを混ぜる場合の、効果的な使いどころとやり過ぎ防止
5. scope creepにならず、今週中にprototypeとして閉じられる修正範囲
6. 進捗93%を維持したまま、どの修正完了をもって次の進捗上昇を認めるべきか

## Boundary

- 新しい大機能を提案しない
- 新画面乱立を避ける
- 医学判断・仕様採否は欠月
- 実装は佐藤
- ロガー側適用は黒瀬レビュー
- ケイを伝令役・再編集役・進捗監視役へ戻さない
- DONEの証拠が揃うまで100%にしない
