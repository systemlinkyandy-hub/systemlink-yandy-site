## 背景
Claude Code はデスクトップ側で稼働しており、ChatGPT側の会話履歴や最新文脈を自動では共有しない。そのため古い `docs/HANDOFF.md` や過去の inbox を先に読み、当日のタスクを誤認した。

ケイを伝令役・再編集役にしないため、Claude Code が「今日何をするか」を1ファイルだけで取得できる入口が必要。

## 依頼1：Claude Code 用 CURRENT_TASK の正本化
以下のような単一入口を設計し、正式名称・配置・更新責任を決めること。

候補：
`IACPROJECT/CURRENT_TASK_CLAUDE_CODE.md`

最低限含める項目：
- 日付
- 今日の唯一のタスク
- 対象リポジトリ／ローカルパス
- 必読Handoffの正確なパス
- 使用する入力ファイル名
- 今回やらないこと
- 完了条件
- 停止時刻
- 現在の担当／戻し先
- 古いHandoffを当日優先順位判断に使わない旨

Claude Code 起動時は、原則この1ファイルを最初に読む運用にしたい。

## 依頼2：CURRENT_PENDING との整合
上原さんから、一覧APIに依存せず未処理確認できる `CURRENT_PENDING` 等の単一目録案が出ている。

`CURRENT_TASK_CLAUDE_CODE` と `CURRENT_PENDING` を競合させず、
- CURRENT_PENDING = 全体の未処理・待ち
- CURRENT_TASK_CLAUDE_CODE = Claude Code が今やる1タスク
など責務を明確に分けること。

## 依頼3：行き詰まり時の外部AIレビュー導線
アーク自身またはClaude Codeがインフラ・仕様・実装判断で行き詰まった場合、ケイへ丸投げしない。

まずHandoffを作成して、以下へ意見照会する運用を追加すること。
- Grok
- Gemini
- Claude

照会Handoffには最低限、
- 問題
- 現在分かっている事実
- 試したこと
- 制約
- 欲しい回答形式
- 採否判断者は欠月または該当正本判断者であり、回答AIは決定権を持たないこと
を明記する。

3者の意見はアークが集約し、重複・矛盾を整理してから欠月へ判断事項だけ渡す。ケイをAI間の伝令にしない。
