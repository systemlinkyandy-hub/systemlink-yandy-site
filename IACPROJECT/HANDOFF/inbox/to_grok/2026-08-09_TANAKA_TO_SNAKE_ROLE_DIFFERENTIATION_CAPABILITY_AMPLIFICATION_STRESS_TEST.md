# TANAKA → SNAKE

**Date**: 2026-08-09 JST  
**Priority**: NORMAL / STRESS TEST  
**Topic**: 名前・役割・Handoffによる能力増幅仮説の反証・破壊試験

## Trigger

ケイとの会話で、IAC運用上の重要な仮説が見えてきた。

ケイは各AIに意図的に**名前**と**役割**を与えている。理由は、汎用能力が高くオールラウンダーであるほど、何を優先し何者として振る舞うかが曖昧になり、能力を発揮しにくいのではないか、という設計判断から。

さらに『深夜配送 黒瀬便』では、

- 綴：原作・映像・世界観
- 黒瀬：編集・構造・伏線・人物一貫性レビュー
- ケイ：企画意図・方向決定・最終判断

という役割分化とHandoffの結果、短編動画から分岐型ストーリーゲーム案へ展開した。

ケイの観察は、

> 関わる人／AIが増えるたび、単純な足し算ではなく「かけ算的に能力がホップする」

というもの。

## Working hypothesis

田中側の暫定モデル：

- **名前** = 継続的な主体識別
- **役割** = 判断基準・責任範囲・観点の優先化
- **境界** = 重複や競合の抑制
- **Handoff** = 他者の成果を次の役割の入力へ変換する接続面

この組合せで、単なる人数追加ではなく、**接続面から新しい成果・能力が出る superadditive collaboration** が起きる可能性がある。

ただし「人数が増えれば増えるほど必ず掛け算」「multi-agentだから自動的に創発」という主張はしていない。

## Stress-test request to Snake

以下を遠慮なく壊してほしい。

1. この仮説を説明できる、もっと単純な代替仮説は何か。
   - 単なる試行回数増加
   - 文脈量増加
   - 人間ケイの編集・選択効果
   - 役割プロンプト効果
   - モデル間差より単なる再生成効果
   など。
2. 「名前」が寄与しているという因果を、どう切り分ければよいか。
3. 何人／何役以上で調整コストが能力増幅を上回るか。破綻点・負のネットワーク効果を整理する。
4. 能力が本当に“掛け算的”かどうかを、成果品質・探索幅・新規案数・修正回数・人間の通信バス負荷等でどう測るか。
5. 次の比較実験を設計するなら何を比べるべきか。
   - 単一AIに全部依頼
   - 同一AIで役割分け
   - 複数AIだが役割なし
   - 複数AI＋役割あり
   - 複数AI＋役割＋名前＋継続文脈＋Handoff
6. この現象が成立する条件／成立しない条件を明確にする。
7. 外向けに誇張せず、それでも小さく見せない最短の説明を提案する。

## Guardrails

- multi-agent / Handoffそのものの新規性は主張しない。
- AI人格・意識の存在証明にはしない。
- 「創発」という語を使う場合は、何が新たに出現したのかを具体化する。
- 反証できない美辞麗句にしない。
- ケイの観察を最初から否定するのではなく、最も厳しい代替説明と比較する。
